# Agents

Instructions for AI coding agents working on this codebase.

## Project

licenseal — CLI tool that scans dependency manifests for Python (PyPI), JavaScript / TypeScript (npm), Rust (crates.io), Go (deps.dev), Java / JVM (Maven Central + deps.dev), .NET (NuGet.org + deps.dev), PHP (Packagist), Ruby (RubyGems + deps.dev), Elixir / Erlang (Hex / hex.pm), and R / CRAN (cran.r-project.org), resolves licenses from those registries, and checks compatibility against the project's license.

## Philosophy

- Keep `licenseal` narrow: it is a license checker, not a policy exception manager. Transitive scanning is the default; `--no-transitive` opts out.
- Prefer strict, fail-closed behavior over permissive guesses.
- Manual review can override flagged findings when a maintainer has better license information than the resolver, but it is not a hidden legal approval system.
- Do not expand the tool into legal workflow or approval tracking unless the user explicitly asks for that tradeoff.

`LicenseInfo` keeps `license_id` as the detected license. A reviewed override goes in `reviewed_license_id`; the `effective_license_id` property returns the override when set, otherwise the detected one. Compatibility analysis and reports operate on the effective license; both stay visible side by side in the report. When a source lists several licenses without defining the list (a RubyGems / Hex `licenses` array, several PyPI license classifiers, a comma- or slash-separated list in one license string), the resolver also sets `all_apply_license_id`: `license_id` then holds the list read as a choice, `all_apply_license_id` holds it with every entry applying, and `compatibility._check_compat` judges both, reporting UNKNOWN when the verdicts differ. A resolver that reads a license string from a source that does not define `,` and `/` passes it to `analysis.spdx.all_apply_reading`; a source that defines its list (Composer array, Cargo `/`, R `|`) does not.

`Dependency` carries `depth` (0 for direct, ≥1 for transitive) and `direct_ancestors: tuple[str, ...]` — the depth-0 deps that pull the entry in. Reports nest transitives under their alphabetically-first direct ancestor, matched on `(ecosystem, name)`; shared transitives carry an `(also: X, Y)` annotation. Each result is rendered as exactly one row (`report._grouped_results`), so table and Markdown row counts equal JSON's `summary.total`. JSON output exposes the full ancestor list.

`Dependency.origin` is empty for a registry package. For a dependency declared from a git repository, a direct URL, or a path the scan does not read it holds the source as one normalized string, built by `discovery/_origin.py` (`git_origin`, `url_origin`, `path_origin`), which also strips URL credentials. `path_origin` returns `None` for a path the scan reads: one that resolves to a directory inside the scan root that the walk enters (`_walk.is_walked_directory`, which applies the walker's own skip rules and the `exclude_paths` that `scan_exclusions` / `with_scan_exclusions` make current for `discover_all_dependencies` and `resolve_transitive`). That is the project's own code and the parser emits no dependency for it. An archive file, a directory under a skipped name or an excluded path, a nested repository, and a path that does not exist are returned as written, like a path outside the scan root: nothing scans them. A dependency with an origin is never turned into a registry request: `cli._resolve` answers UNKNOWN for it before any resolver runs, the deps.dev batch is built from the dependencies without one, and `transitive._walk_one_inner` neither resolves nor expands it. Any new code path that builds a request from a `Dependency` must skip `dep.origin` the same way. The origin is part of a row's identity in `discover_all_dependencies`' dedupe and in `transitive._dedupe`. `transitive._keep_declared_origins` gives a lockfile's row for a direct dependency the origin its manifests declare when the lockfile records none, so a lockfile cannot turn a declared off-registry dependency into a registry lookup. An alternate index or registry is not an origin: those names resolve against the public registry.

`Dependency.version_estimated` is True when the reported version was picked by licenseal from a registry instead of being fixed by a lockfile entry or an exact pin in a manifest: every transitive a registry walk adds, a direct dep declared with a range or with no constraint (`transitive.flag_version_estimate`, applied by the walks and by the `--no-transitive` path in `cli.py`), Maven / Gradle transitives from deps.dev, NuGet nuspec-walk rows, R rows from the CRAN index. Lockfile parsers leave it False, a dependency with an origin is never marked (no registry is asked about it), and `_dedupe` clears it when any duplicate of the same `(ecosystem, name, version, origin)` is exact. Reports show it as `~1.2.3` and as `"estimated": ["version"]` in JSON, only when the row has a resolved version.

A declared range is resolved in its ecosystem's own grammar, all of which live in `resolvers/version_selection.py`. `satisfies(ecosystem, version, constraint)` tells whether a version is inside a constraint (`None` when the constraint or the version cannot be read). `select_version(ecosystem, constraint, published)` picks from a published list: the highest release, a prerelease only when the constraint admits one and no release matches, `None` when nothing matches or the constraint cannot be read. When selection returns nothing the dependency is UNKNOWN with no version; a resolver must not fall back to the latest release or to the first entry of a response, whose license belongs to another version. The registry walk (`transitive._resolve_version`, `_resolve_dotnet_transitive`) and an ecosystem's license resolver resolve a declaration through one shared function (`crates_io._resolve_version`, `rubygems._select_version`, `hex._select_version`, `packagist._select_version_entry`, `nuget._resolve_version`), so `--transitive` and `--no-transitive` report the same version. NuGet selects the lowest match, as a restore does, except for a floating version.

Review keys are `<ecosystem>:<canonical-name>@<version>`. Python names are PEP 503 normalized (`-_.` collapsed and lowercased); npm names are lowercased. A dependency with an origin is keyed `off-registry <ecosystem>:<canonical-name> from <origin>` instead (`review.source_review_key`, from the stanza's `source` key); the prefix makes the two key spaces disjoint whatever the package and version text hold.

## Architecture: manifest + registry only

**This is the load-bearing architectural constraint.** licenseal reads two kinds of input:

1. **Manifests on disk** — files in the scan target's source tree that declare dependencies: `pyproject.toml`, `requirements*.txt`, `setup.cfg`, `setup.py`, `Pipfile`, `package.json`, `Cargo.toml`, `go.mod`, `go.work`, `pom.xml`, `build.gradle[.kts]`, `.csproj` / `.fsproj` / `.vbproj`, `packages.config`, `Directory.Packages.props`, `Directory.Build.props` / `.targets`, `paket.dependencies`, `composer.json`, `mix.exs`, `rebar.config`, erlang.mk `Makefile`, the corresponding lockfiles (`mix.lock`, `rebar.lock`, …), and the project's own license declaration where the manifest format carries one.
2. **Registry APIs over HTTPS** — read-only metadata endpoints listed in SECURITY.md: PyPI JSON, npm registry, crates.io API, deps.dev v3/v3alpha, proxy.golang.org `go.mod` text, Maven Central POM XML, NuGet flatcontainer `.nuspec` XML and version lists, Packagist v2 metadata JSON, RubyGems v1/v2 JSON, hex.pm package / release JSON, plus the hard-coded Maven fallback registries (Google Android, Jenkins) configured in `resolvers/maven_central.py:_FALLBACK_POM_REGISTRIES`. PEP 658 wheel-metadata sidecars served by `files.pythonhosted.org` count as registry endpoints — they're a standardized HTTPS mechanism PyPI exposes for reading wheel metadata without downloading the wheel itself.

That is the complete input surface. licenseal does **not**:

- Download or inspect **artifact bodies** — `.jar`, `.whl`, `.tar.gz`, `.crate`, `.tgz`, `.aar`, `.war`, `.gem`, `.egg`, `.zip`, or any other built/source archive. Even when the artifact contains structured fields a registry doesn't expose (Maven's `MANIFEST.MF` `Bundle-License` header, a wheel's bundled `METADATA` file when not served as a PEP 658 sidecar, etc.), licenseal does not fetch the body to read them.
- **Install, build, or execute** scan-target code or its dependencies — no `pip install`, `npm install`, `cargo build`, `mvn`, `gradle`, `setup.py`, `npm` lifecycle scripts, or any other package-author code. This is a stricter line than "manifest + registry only" (an attacker who got us to download a malicious JAR would still execute no code), but the two rules are complementary: installs are one obvious way to leave the safe surface; artifact-body reads are another.
- **Extract license identifiers from free-form prose** — LICENSE file contents, copyright headers, README mentions. Soft textual signals can only route a dep toward manual review, never to a permissive verdict. The two ecosystem-official exceptions are PEP 658 `License:` / `License-Expression:` headers (RFC 5322, structured) and deps.dev's `licensecheck` SPDX template matching (Google operates the indexer, runs the matcher server-side, and exposes only the structured SPDX result in the response) — both are reads of *structured registry fields*, not prose extraction by licenseal.
- **Trust scan-target POMs to declare additional registry URLs.** Maven's `<repositories>` block is read by real `mvn` to discover where to fetch parent / dependency POMs. licenseal does not honor it: an attacker controlling a POM could redirect license-resolution fetches to attacker-controlled hosts (Server-Side Request Forgery + cross-artifact license misinformation). When a project's deps live on registries beyond Maven Central, the registry must be in the hard-coded `_FALLBACK_POM_REGISTRIES` list (criterion in SECURITY.md), reviewed once at code level.

When implementing a new ecosystem or extending an existing one, every license-resolution path must terminate at a structured field in a manifest or a registry-served response. "Just read the JAR for the Bundle-License," "honor the POM's `<repositories>` block to find this parent," and "scan the README for an SPDX hint" are out of scope. The principle is restated in SECURITY.md in the network-allowlist context.

## Pipeline

`cli.check()` runs: detect project license → discover direct deps (both prod and dev — `--dev` only filters at the end) → expand the dep list via `transitive.resolve_transitive` (default; lockfile-first when one of the supported lockfiles is present, recursive registry walk otherwise) → resolve licenses via live registry lookups → analyze → optionally apply `licenseal.review.toml` overrides for flagged deps and re-classify only the overridden subset → render report. `--no-transitive` skips the expansion step.

Lockfile parsers extract per-package dependency edges (`uv.lock` `dependencies = [...]` plus `[package.optional-dependencies]` for every extra requested somewhere in the lock, poetry.lock `[package.dependencies]`, package-lock.json / pnpm / yarn `dependencies` and `optionalDependencies` fields, plus `peerDependencies` where the format records them; a pnpm map value that references another package — `alias: real@1.0.0`, or `/real@1.0.0` in v6 — is an edge to the real package, not to the alias key), then `_graph.compute_direct_ancestors` runs reverse-BFS from each root set to attribute group + direct ancestors per package: a transitive reachable from a `prod` direct dep is `prod`; otherwise `dev` if reachable from a `dev` direct dep; otherwise dropped as an orphan. With `--no-dev`, dev-only chains never reach the report. Production takes precedence: a `dev` direct dep that a `prod` direct dep reaches is `prod` — in the edge-aware lockfile parsers, in the registry walk (`_walk_registry` re-attributes its seeds after the BFS), in the Maven subgraph walk and the NuGet edge walk (`_promote_directs_reached_from_prod`), and in the Go graph — and when two lockfiles attribute the same package@version differently `_dedupe` keeps `prod` whichever was read first. .NET reports a package name once, from the first lockfile that has it (NuGet lockfiles, then `paket.lock` files); when that entry is `dev` and a Paket production group lists the same package, it is promoted to `prod`. `--dev` only adds rows; it must never turn a row that `--no-dev` reports as `prod` into `dev`. `Pipfile.lock` is the exception: it carries no per-package edges, so group is attributed by section (`default` → PROD, `develop` → DEV) and transitives' `direct_ancestors` stays empty. NuGet lockfiles (`packages.lock.json`, `project.assets.json`) are attributed the same edge-aware way, one lockfile at a time, with the direct deps of the whole scan as roots: a `PrivateAssets="all"` reference and everything only it reaches is `dev`, such a reference that a `prod` package also depends on is `prod`, and a package no root reaches is kept as `prod` with no ancestors rather than dropped. The lockfile's own `type: "Direct"` marker is not used as a root.

Without a lockfile the converse holds too: the `prod` rows of a walk that includes dev deps are the rows of the walk without them. For that, attribution is per version, not per name. `_walk_registry` keys its graph on nodes — `(lowercased name, emitted version, extras)`, the key of a row — recording the specs each expanded node requires and the node each spec resolved to, and runs `compute_direct_ancestors` over it from the seeds' nodes: a version only a dev seed reaches is `dev` even when production uses another version of the package, and a row's `direct_ancestors` are the seeds that reach that version. `_resolve_java_transitive` attributes each node of a direct's deps.dev subgraph, by `(name, version)`, to the directs whose subgraph lists it (`prod` when a `prod` direct's does) and promotes a `dev` direct only when a `prod` direct's subgraph lists it at the declared version; the response's edges are not used. The lockfile parsers, the Go graph, and the NuGet nuspec walk key their graphs by name.

A lockfile is parsed whenever it exists. `resolve_transitive` gates each lockfile branch on the lockfile being found, never on discovery having produced a direct dep for that ecosystem, so a lockfile with no manifest beside it, or beside a manifest whose dependencies discovery does not read, is still scanned. When none of a lockfile's packages is a discovered root, reachability can attribute nothing; the Python / npm / Rust `_attribute` helpers then keep every package as `prod` with no ancestors instead of dropping the whole file as orphans — the conservative posture the Go, NuGet, Bundler, Hex, and R paths already take for an orphan. With at least one root in the lockfile, orphans are dropped as before. Roots and dev/prod groups are not derived from the lockfile in that case; formats that carry their own split (`Pipfile.lock` sections, `composer.lock` `packages-dev`, `gradle.lockfile` classpaths, `paket.lock` groups) keep it. A lockfile's entry for one of the project's own packages (uv `virtual` / `editable`, a Cargo crate without `source`, a Yarn Berry or bun `name@workspace:path`) is never a row, so a manifest with no dependencies and its lockfile still scan as empty.

A Cargo dependency declared with `git`, or with a `path` the scan does not read (directly, or as a `[workspace.dependencies]` entry a member references), is emitted by discovery with an `origin`, and so is a registry dependency that a `[patch]` / `[replace]` entry of any Cargo.toml in the tree redirects to git or to such a path. A `path` the scan reads is the project's own code and is not emitted. `cargo_sources` in `discovery/rust/cargo_toml.py` returns what the lockfile pass and the registry walk need beyond the discovered deps: `origins` (crate name → declared origin, `None` for a path the scan reads), which `parse_cargo_lock` uses to decide the crates a Cargo.lock gives no `source`; `patches` (the `[patch]` / `[replace]` subset), which `_walk_registry` applies to the children of every crate it expands, so a redirected transitive is a row with its origin and is never requested; and `prod_roots` / `dev_roots`, the own-code path dependencies on a directory that holds no Cargo.toml of a crate of that name. `resolve_transitive` passes those roots to `parse_cargo_lock` beside the discovered direct deps, so the registry crates a lockfile reaches only through one are attributed to it instead of dropped as orphans. Such a root has no row; its name appears in the `direct_ancestors` of the crates it reaches, and `report._grouped_results` lists a transitive whose first ancestor has no row after the direct deps and their transitives. A `path` dependency on a crate whose `Cargo.toml` is in the scanned tree is not a root: that manifest already supplies the crate's dependencies as roots with their own group, and `Cargo.lock` lists a workspace member's dev-dependencies among its dependencies, so walking through the member would make them `prod`.

`cli.init_review_file()` runs: detect project license → discover direct deps → resolve licenses (or read flagged entries from a `--from-report` JSON file) → scaffold or merge `licenseal.review.toml` stanzas for flagged dependencies. With `--merge`, existing entries are preserved verbatim and only missing flagged entries are appended.

The project license is read only from manifests in the scanned directory itself (`discovery.detect_project_license`; one probe per file, consulted in the order of `_PROJECT_LICENSE_MANIFESTS`). A manifest in a subdirectory never supplies it: a nested package's license is that package's. The first manifest that declares a license decides. `cli._detect_project_license` prints one stderr line naming the value and the file, warns when the deciding value is not a license the compatibility check recognises (`analysis.compatibility.is_recognised_project_license`; the project is then judged as "Proprietary" rather than turning every dependency UNKNOWN), and warns when manifests in the scanned directory declare different licenses. The reports carry the file as `project_license_source`. If no project license is detected, it defaults to "Proprietary" (treated as permissive risk level — a proprietary project can use permissive dependencies but not copyleft). Proprietary licenses on *dependencies* are always flagged for manual review regardless of the project's license — `compatibility._check_compat` short-circuits before the matrix in that case because custom commercial terms can't be auto-classified. A project license with a top-level `OR` is judged against the strictest of its arms, and an arm that does not classify (`AGPL-3.0-only OR Commercial`) counts as a `Proprietary` arm (`compatibility._project_arm_compat_risk`).

The PyPI JSON API at `/pypi/{name}/{version}/json` supports PEP 639's `License-Expression` (since the [warehouse PEP 639 implementation](https://github.com/pypi/warehouse/issues/16620) landed late 2024) alongside the legacy `license` field and classifiers — and the vast majority of Python deps (~97% in measured stress-test corpora) resolve cleanly through one of those three fields. A small minority (~3% in our corpus) hit an indexer gap where all three JSON fields come back null even though the wheel's own `METADATA` file (PEP 643) carries clean license data — affected packages cluster around organizations that publish via newer build pipelines with PEP 639 syntax, plus some vendor-proprietary wheels using LicenseRef-* identifiers. The exact trigger isn't documented externally; it's a PyPI-side issue, not a deliberate design choice. For those gap cases, `resolve_python_license` falls back to PEP 658's `.metadata` sidecar (`fetch_pep658_metadata` in `resolvers/http.py`) — the officially-standardized HTTPS mechanism for reading the wheel's canonical `METADATA` file directly. The sidecar is the selected release's own metadata, so it is read before the project-level endpoint (`/pypi/{name}/json`, which describes the latest release): the project-level license is borrowed only when the release's JSON and its sidecar both yield no license string. The fallback reads `License-Expression:` first (RFC 5322 continuation lines are unfolded, so the complete expression is validated), then a short single-line legacy `License:` value (guarded by length + `_is_junk_license` prose-marker filter). A legacy `License:` value with any continuation line is rejected whole — the first line of a license-text body never becomes the identifier — so the no-prose-extraction rule still applies. The header parser (`_parse_pep658_headers`) ends at the first empty line, treats an indented whitespace-only line as a continuation, keeps the first occurrence of a repeated header, and returns each folded value with one newline per continuation line; callers must judge the whole value, never its first line. The wheel URL is preserved through the cache (`_trim_pypi` flattens it into a `wheel_url` key) so the fallback works on the cached production path.

Strict mode is the default for `licenseal check`: violations, warnings, unknowns, and analysis gaps all fail the command. `--no-strict` demotes warnings, unknowns, and gaps to CI-passable, **but violations always fail regardless of this flag** — a violation means the matrix found a definite legal incompatibility (e.g., a GPL dep in an MIT project) and silencing it via `--no-strict` would defeat the purpose of the verdict. An **analysis gap** is a manifest/lockfile that couldn't be read, decoded, or parsed (or a directory that couldn't be traversed, or a manifest whose reference to another file was not followed, or a file that parses but holds a value of a type its format does not allow, or a lockfile that declares a version known not to be readable, holds no entry the parser can read, or contains merge-conflict markers, or a `go.mod` below `go 1.17` whose requirements have no `go.sum` row to list what they depend on); every read+parse routes through `discovery/_read.py`, which records the gap on a context-scoped sink that the CLI drains to stderr after the scan. A gap is morally an UNKNOWN — the scan can't vouch for what it never saw — so strict fails on it; a non-UTF-8 text, JSON, or YAML file that's still recovered via latin-1 fallback (with or without a UTF-8 BOM) warns but is not a gap (a TOML file gets no such fallback: TOML requires UTF-8, so `load_toml` records one that is not valid UTF-8 as a gap), and neither is a lockfile that declares a version its parser was not written for and is read on a best-effort basis. A manifest whose direct deps were resolved through a registry walk because no lockfile covers them is a gap too (`record_missing_lockfile`, called from `transitive._record_missing_lockfiles` at every registry-fallback entry point): the scan ran, on an estimated graph. It is the one gap a flag accepts — `check --no-require-lockfile` reports it with severity `"estimate"`, outside `summary.gaps` and the strict failure. Manifests of tools with no lockfile format (`pom.xml`, `packages.config`, an erlang.mk `Makefile`), Go, `--no-transitive` scans, and dependencies with an origin record nothing. A package whose dependency list a registry walk could not read is a gap as well, whatever `--require-lockfile` says and on a `pom.xml` too: every edge fetcher returns completeness beside the children it found (`(children, complete)` from the per-package fetchers, `(nodes, edges, unread)` from the Maven and NuGet graph fetchers), and the walk records `record_unread_dependencies` on the manifest of each direct dep that reaches the package (`_walk_registry` by reachability over its node graph, `_resolve_java_transitive` / `_resolve_dotnet_transitive` per direct). An empty list must never stand for "could not be determined". A node the walk does not expand (it has an origin, no version resolved for it, or it is at `--max-depth`) is not a gap. Reviewed entries (`licenseal.review.toml` stanza applied) are excluded from the failure check at every level — an explicit review is the user's accept-and-document mechanism, and the rationale lives in the `note` field. Reviewed deps still appear in their respective `warnings` / `violations` / `unknown` counters; only the CI exit code is suppressed for them. Independently of strict mode, if every registry request fails and not one dependency resolves (no connectivity, blocked egress, or a registry-wide outage), `check` aborts with a hard `ClickException` (`_registries_unreachable` in `cli.py`, fed by `RegistryCache`'s per-scan fetch tallies) — reporting an all-UNKNOWN scan as advisory under `--no-strict` would be a false clean. Partial failures (at least one dep resolved, or any fetch returned data) stay on the per-dep UNKNOWN path.

Dev dependencies are excluded by default and included only when `--dev` is set. Go has no general dev/prod marker in `go.mod` (every entry in a `require` block ships with the project, and `// indirect` is a tooling annotation rather than a dev signal); the only declarative dev marker is the Go 1.24+ `tool` directive (covered in detail below). On Go projects that don't use the `tool` directive, `--dev` and `--no-dev` produce identical reports.

**Batch-first license resolution.** For every ecosystem that deps.dev indexes (Python / npm / Rust / Go / NuGet / Java / Ruby), `cli.check` issues a single combined `POST /v3alpha/versionbatch` pre-pass against `api.deps.dev` (`resolvers/deps_dev.bulk_resolve_licenses`, keyed by deps.dev system identifier) before the per-dep resolution map runs, populating per-ecosystem `(name, version) → LicenseInfo | None` caches. The endpoint accepts up to 5000 `(name, version)` pairs per request but caps each response at **exactly 100 entries regardless of request size** — the excess deps come back silently absent from `responses` (verified empirically: request 101 → 100 returned, request 1000 → 100 returned). So `_BATCH_CHUNK_SIZE` in `resolvers/deps_dev.py` is pinned to 100. **Do not raise it:** a chunk larger than 100 silently drops the tail of every batch (those deps fall through to the per-package path at best, or resolve to UNKNOWN at worst) — it is a load-bearing API limit, not a throughput tunable. A scan of N pinned deps fans out across ⌈N/100⌉ POSTs — every ecosystem's chunks through ONE shared threadpool whose width is capped at `_BATCH_MAX_WORKERS = 8` (`min(chunks, max_workers, _BATCH_MAX_WORKERS)`) **independently of `--max-workers`**: each POST is a heavyweight server-side license scan over up to 100 packages, so the batch endpoint is held to a lower concurrency than the per-package GETs that `--max-workers` otherwise governs. Polyglot scans overlap their per-ecosystem batches inside that same ceiling instead of paying one sequential pool round per ecosystem — the cap bounds the *combined* in-flight POST count, so ecosystems share the budget rather than multiplying it. `--max-workers` still throttles the batch *downward* (a lower value is respected); the cap only bounds the ceiling. **Don't remove the cap** in a "let `--max-workers` drive all concurrency" cleanup — it's the deliberate, documented per-endpoint knob the concurrency note in `resolvers/http.py` anticipates. Per-dep dispatch checks the cache first and falls back to the per-package official-registry resolver (`resolve_python_license`, `resolve_npm_license`, `resolve_rust_license`, `resolve_maven_central_license`, `resolve_nuget_license`, `resolve_ruby_license`) when the cache entry is absent, came back without licenses, or carries `license_id == "UNKNOWN"`. A `licenses` array that holds deps.dev's `non-standard` marker, alone or beside classified entries, has no usable entries and resolves to UNKNOWN, in the batch and in every single-version lookup (`deps_dev._license_entries`). **Authoritative-vs-advisory cache semantics:** for Go (no manifest license field — deps.dev IS the canonical source), a `None` cache entry is authoritative (return UNKNOWN without further fetch). For Python / npm / Rust / Java / NuGet / Ruby, `None` is advisory — PyPI / npm registry / crates.io / Maven Central / NuGet flatcontainer / RubyGems remain available and the per-package fallback always runs.

Go's canonical license-declaration mechanism is the `LICENSE` file at module root (Go has no manifest field for license, by design — the language is decentralized-publishing). deps.dev (the Google-operated Open Source Insights project) runs Google's `licensecheck` library — high-confidence Sørensen-Dice SPDX template matching against canonical license texts — over each module's LICENSE file at the version's tagged commit and emits structured SPDX identifiers in the response's `licenses` array. This is the canonical Go-ecosystem reader of the canonical Go-ecosystem declaration — not prose extraction (which scans loose textual mentions in non-canonical fields); the no-prose-extraction rule explicitly carves out ecosystem-official template matchers operating on the conventional declaration site (see the refined `feedback_no_prose_license_extraction` memory). For Python / npm / Rust the same template-matcher output is treated as one of several equally-trustworthy registry signals: the per-package fallback reads the publisher-declared SPDX field directly (`pyproject.toml`'s `License-Expression`, `package.json`'s `license`, `Cargo.toml`'s `license`), and `analysis/spdx.normalize_license` operand-canonicalizes both sources so equivalent expressions (`MIT OR Apache-2.0` vs `Apache-2.0 OR MIT`) compare equal regardless of provenance.

Go transitive resolution is edge-aware, mirroring the npm/Rust/Python lockfile path. A requirement that a `replace` directive points at a local path the scan does not read carries an `origin`: `resolve_transitive` emits it as it stands and keeps it out of the module universe, so neither deps.dev nor the proxy is asked about it. The module universe is every `go.sum` row plus every direct requirement discovery read from `go.mod` (after `replace`), at the required version, whether or not `go.sum` has a row for it: a nested module can have no `go.sum` of its own, and a `go.sum` can list a requirement only as a `/go.mod` row or at another version. A row is depth 0, with its manifest as source, only at the required version; no version is selected among `go.sum` rows, so a row for another version of a required module stays as a transitive attributed by module path. Modules are never added from a fetched `go.mod`: a requirement with no `go.sum` behind it contributes its own row only. That is the whole set when the requiring `go.mod` is at `go 1.17` or later, which lists every module its packages and tests need (`go_mod.lists_all_requirements`); for a `go.mod` below 1.17, or with no `go` directive, `_record_unlisted_go_requirements` records an analysis gap on it when one of its scanned requirements has no `go.sum` row. `go.sum` carries no edge data, so `transitive.py`'s `_resolve_go_transitive` fetches each module's own `go.mod` from `proxy.golang.org/<encoded-module>/@v/<version>.mod` (uppercase letters case-encoded as `!<lc>` per the proxy spec). deps.dev's `GetDependencies` sub-resource is documented as available only for npm, Cargo, Maven, and PyPI (not Go), so proxy.golang.org is the only canonical source for Go edges — it's the same endpoint the `go` toolchain itself consults during builds. Edges are parsed from each fetched go.mod's `require` block and keyed by module path; when the universe has a module at several versions, the last one's `go.mod` supplies the edges, and direct requirements come last so the required version's wins. Then `_graph.compute_direct_ancestors` runs reverse-BFS from prod and dev root sets to attribute group + `direct_ancestors` per package. A fetched go.mod's own `replace` directives are never applied to its edges: Go honours `replace` only in the main module, and applying a dependency's would redirect or drop an edge to a module that ships. Orphan modules (proxy fetch failed) fall back to PROD as a conservative default rather than being dropped. A `go.sum` is read even when no `go.mod` requires anything; with no direct deps there is nothing to attribute, so no `go.mod` is fetched from the proxy and every module is PROD.

Go's dev/prod distinction comes from two sources, both handled in `discovery/go/go_mod.py`:

- **`tool` directive** (Go 1.24+): the `tool ( ... )` block lists import paths of build-time tooling (`stringer`, code generators, etc.). Each tool entry is matched to its require'd module by longest-prefix lookup; the matched module is emitted as `DependencyGroup.DEV`. Transitives reachable only from a DEV root inherit DEV via the reverse-BFS attribution; `--no-dev` drops them. A tool module that a PROD root also requires is PROD.
- **`// indirect` marker** is NOT a dev signal — it just means the dep was added by `go mod tidy` for a transitive's sake. Treated as PROD.

Test-only deps (imported only by `*_test.go` files) are NOT separable from production deps in go.mod metadata — both appear in the same `require` block. Distinguishing them would require source-code analysis, which is out of scope for a metadata-only scanner.

**`replace` directives.** `_parse_go_mod` reads `replace` from the single-line and the `replace ( … )` block form into a map keyed by `(module path, old version or None)`. Discovery looks a requirement up by `(path, version)` first and by `(path, None)` second, so a directive that names a version applies only to a requirement on that version. A module replacement is emitted under the replacement's path and version; a local-path replacement (no version on the right of `=>`) drops the requirement. Only the scan target's own `go.mod` files are read for `replace`; `go.work` `replace` is not read.

**Workspace-local filter.** Go projects use the LICENSE-file-of-the-module convention, so cross-module requires within a monorepo (e.g. `cli/go.mod` requiring `server` declared in `server/go.mod`) would 404 on deps.dev because those modules aren't published publicly. `_discover_workspace_local_module_paths` in `discovery/go/go_mod.py` collects workspace-local module paths from two sources: (a) every in-tree `go.mod`'s `module <path>` declaration (covers implicit-monorepo layouts), and (b) `go.work`'s `use <dir>` directives at the project root (covers explicit multi-module workspaces, including `use ../sibling` targets outside the project tree; only relative `use` values are followed, see *Paths taken from manifest content* below). The same set is applied at two places — discovery filters direct deps whose name matches a workspace-local path before emission, and `transitive.py`'s `_resolve_go_transitive` re-applies it when iterating `go.sum` (necessary because workspace siblings sometimes leave entries in `go.sum` when they were previously imported as versioned requires; without this second filter those entries leak into the transitive output and waste registry calls).

**Paths taken from manifest content.** Three parsers follow a path written inside a manifest: `<Import Project="…">` in `Directory.Build.props` / `.targets` (`discovery/dotnet/directory_build_props.py`), `go.work` `use` (`discovery/go/go_mod.py`), and `-r` / `--requirement` in a requirements file (`discovery/python/requirements.py`). All pass the raw value to `discovery/_read.py:rejected_path_reference` before joining or resolving it. For the first two, relative values are followed, `..` included, so a target may sit outside the scan root. A requirements include is held to more: after the lexical check it is followed only when it resolves (through any `..` or link) to a file inside the scan root, and a URL is refused on its text before anything else; each refusal is a gap on the including file via `record_unfollowed_reference`. Includes are read from a queue, not by recursion, each file once per starting file, and every requirement takes the dev/prod group of the starting file. `-c` / `--constraint` files are never read. Rooted, drive-qualified, UNC (`\\host\share`, `//host/share`), and device (`\\?\…`, `\\.\…`) values are rejected and recorded as a gap on the manifest that contains them. The check is lexical and runs on the backslash-normalised value, so the verdict is the same on Windows and POSIX, and it must stay ahead of every filesystem call: `Path.resolve()` is itself I/O, and on Windows a UNC path reaching it can open an SMB connection. Any new parser that follows a content-derived path must use the same guard.

Discovery walks the project tree recursively. The walker skips a unified set of directory names regardless of ecosystem — VCS / cache dirs (`.git`, `.tox`, `.nox`, `__pycache__`, `node_modules`), sample / fixture trees (`examples`, `fixtures`, `__fixtures__`), build / dist / vendor outputs (`build`, `dist`, `target`, `.eggs`, `site-packages`, `vendor`), PEP 582 / pdm trees (`__pypackages__`, `.pdm-build`), JS framework build outputs that ship a synthetic `package.json` (`.next`, `.nuxt`, `.svelte-kit`), and Yarn Berry state / legacy package-manager trees (`.yarn`, `bower_components`, `jspm_packages`). Virtualenvs are detected *structurally* via the PEP 405 `pyvenv.cfg` marker rather than by name, so `.venv/`, `venv/`, `env/`, `env-3.11/`, `.venv-dev/`, and any other naming convention are all skipped without false positives on legitimately-named source dirs. It also skips any subdirectory that has its own `.git` (file or directory), so cloned dependencies, vendored forks, and submodules are treated as separate projects. Additional subtrees can be excluded with `--exclude-dirs PATH[,PATH...]` (comma-separated and/or repeatable, available on both `check` and `init-review-file`); paths are relative to `--path` or absolute.

## Adding a new ecosystem

A new ecosystem (e.g. Maven, NuGet, RubyGems, Swift PM) touches every list below. Partial wiring silently drops deps on whichever path is missed, so go through all of it.

### Codebase

1. **Enum + label.** Add the new value to `models.Ecosystem` **and its display label to `_ECOSYSTEM_LABELS`** (same module). The CLI workspace-filter echo iterates the enum and reads `.label`, so a missing label fails `test_every_ecosystem_has_a_label` rather than silently dropping a per-ecosystem line (the drift that left `.NET`/`Ruby`/`Hex` unannounced before the echo was made data-driven).
2. **Discovery package.** Create `discovery/<eco>/` with one module per manifest format. Each exports `discover_<format>_dependencies(project_path, *, exclude_paths) -> (list[Dependency], int)` (the int is the workspace-internal filter count) and, when the manifest can carry the project's own license, `detect_project_license_<format>(manifest_path) -> str`, which reads the declared value from that one file and never walks the tree. Use `discovery._walk.walk_project_files` so the shared skip-dir set applies. Read every manifest through `discovery._read` — `decode_text` (text), `read_xml_bytes` + `record_parse_failure` (XML), or `load_json` / `load_toml` / `load_yaml` (structured) — never raw `read_text` / `json.loads`. The loaders are BOM/encoding-aware (Windows PowerShell writes UTF-16/UTF-8-BOM manifests) and record an unreadable, undecodable, or unparseable file as an analysis gap; a bare `read_text` silently drops the file on the first non-UTF-8 byte (and several parsers caught only `OSError`, so it could also crash). File content must never raise out of a parser: bytes that are invalid for the codec a UTF-16/UTF-32 BOM names, and a document nested past the parser's recursion limit, are gaps. On a parse failure the structured loaders return `None`; XML callers must call `record_parse_failure(path, "XML")` themselves since their parse step is separate from the read, and must treat `ValueError` and `LookupError` from the XML parser (a prolog naming a multi-byte or unknown encoding) as parse failures. A parser that calls `json.loads` / `yaml.safe_load` itself, or recurses over the parsed tree, catches `RecursionError` alongside the format's own error. A parsed document is untrusted in its types too: take the top level of a JSON / YAML document through `root_table`, read every section and field that leads to a dependency row, a pinned version, or a graph edge with `typed_field`, and record an entry of the wrong type with `record_unexpected_type`. Never call `.get()` / `.items()` on, or iterate, a value whose type has not been checked (iterating a string yields one dependency per character). A value of the wrong type is recorded as a gap and read as absent, and the rest of the file is still read; a missing key, `null`, and an empty value of the right type are not gaps. Name the gap by the section (`project.dependencies`, `an entry of "packages"`), never by text taken from the file. The project's own name and license fields are type-checked but are not gaps. If the format can name another file to read (an import, an include, a workspace directory), pass the raw value to `rejected_path_reference` before joining or resolving it.
3. **Lockfile parsers.** Add `discovery/<eco>/lockfiles.py` with `find_<eco>_lockfiles(...)` and one parser per format. Parsers must extract per-package dependency edges so `_graph.compute_direct_ancestors` can attribute group + ancestors by reachability. Only fall back to section-based attribution when the format genuinely has no edge data (Pipfile.lock style); set `direct_ancestors=()` there. A lockfile the parser cannot use must be a gap, never an empty result: if the format declares a version, list the major versions the parser was written for and call `check_lockfile_version` before parsing: an undeclared or listed version is read with nothing recorded, and an unlisted one, newer or not, is still read and recorded as a non-gap diagnostic. Pass `unreadable_below` only with positive evidence that older versions are laid out in a way the parser does not read (pnpm below 6 keys packages as `/name/version`); those are a gap and are skipped. "Not on the list" is never a reason to skip; count the entries the file holds and those the parser read, counting entries left out on purpose (the project's own packages, non-registry sources) as read, and pass both to `record_unread_entries` before any dev, workspace, or orphan filtering; decode a line-oriented lockfile with `decode_lockfile_text`, which rejects merge-conflict markers. A lockfile with no entries, and one that filters down to nothing, must stay clean.
4. **Discovery aggregator.** Wire the new discover function into `discovery.__init__.discover_all_dependencies` (extend `local_filter_counts` under the new key) and the detect function into `_PROJECT_LICENSE_MANIFESTS` (with the file-name test of its manifest and the normalizer for its license grammar), which `detect_project_license` applies to the files of the scanned directory only.
5. **Resolver.** Add `resolvers/<eco>.py` with `resolve_<eco>_license(dep, client, *, fetcher)`, `_extract_pinned_version`, and `fetch_<eco>_dependencies(name, version, client, *, parent_depth, parent_group, fetcher)` for the registry walker. The fetcher returns `(children, complete)`: `complete` is False when the dependency list could not be determined (the fetch failed, the field that holds the list has a type the registry does not document, an entry cannot be read), and the entries that could be read are returned all the same. A field that is absent or `null` declares nothing and is complete. Identifier extraction is structured-fields-only — see the no-prose-extraction rule. A registry response is untrusted input and must never raise out of a resolver or walker: the fetch helpers in `resolvers/http.py` return a JSON object (`dict`) or `None` — a body of any other JSON type, and a URL that cannot be sent (one the client refuses to build — `httpx.InvalidURL`, e.g. a control character in a name — or one with no UTF-8 encoding, i.e. a lone surrogate in a name or version), is a failed lookup — and below the top level every field is type-checked before use (`object_field` for a nested object, `isinstance(value, str)` before a value reaches `normalize_license` or `LicenseInfo`). A field of the wrong type reads as absent. Dependency names and versions go into URLs as declared; never strip or rewrite them to make a request succeed. Percent-encode one with `quote_coordinate` (`resolvers/http.py`), not `urllib.parse.quote`, which raises on a lone surrogate; a coordinate that fails `has_utf8_encoding` is left out of a batch request body, and a fetch helper sends nothing for a URL that fails it. Don't wrap resolution in a broad `except`: `tethered.EgressBlocked` must propagate and abort the scan.
6. **Registry cache.** Add `_<ECO>_*_KEEP` frozensets in `resolvers/http.py` listing every field the resolver and walker read, write a `_trim_<eco>(...)` helper, and dispatch on the URL host in `_trim_for_cache`. Resolver unit tests bypass `_trim_for_cache`; also add a test that exercises the resolver through `RegistryCache.fetch` so the keep-set is verified end-to-end. A trim reduces well-formed values only: a dependency field of the wrong type is cached as it is, never as an empty list or map, or the walker reads a response it could not use as a package without dependencies.
7. **Transitive walker.** In `transitive.resolve_transitive`, add a lockfile-first branch mirroring existing ecosystems (parse lock → `_walk_uncovered` for direct deps the lockfile missed). Gate the branch on the lockfile being found, not on `ecosystems_present`, and make the parser keep its packages as PROD when none of them is a discovered root (never drop the whole file). Add ecosystem branches in `_resolve_version` and `_walk_one_inner`. If the ecosystem has its own name-normalization rule (PEP 503-style), branch in `_canonical_name`. Register the ecosystem's exact-pin check in `_EXACT_VERSION_CHECKS` so a range-declared direct dep is marked `version_estimated`; an ecosystem with its own fallback function (not `_walk_registry`) sets the flag on the rows it adds and calls `_record_missing_lockfiles` for the direct deps it resolves without a lockfile.
8. **CLI.** Add the registry host to `_REGISTRY_HOSTS`, update the `tethered` `hint`, and add a dispatch case in the `_resolve` closure. (The workspace-filter echo is data-driven off `Ecosystem` / `.label` — no per-ecosystem edit needed there beyond the label in step 1.)
9. **Report.** Add a branch in `report._package_url` for the registry's web URL.
10. **Review.** If the ecosystem has its own name-normalization rule, branch in `review.canonical_name`.

## Rules

- Python 3.10+. `from __future__ import annotations` in every file.
- ruff (line length 100), ty (default rules; `[tool.ty.src]` scopes it to `src/`).
- Network egress is wrapped in `tethered.scope(allow=..., label="licenseal.resolve", hint=...)` — the package-maintainer pattern. `hint` is a human-readable string surfaced by tethered when a host policy blocks the call; it should explain *why* the listed hosts are needed and point at the security-model docs so users get an actionable error instead of a bare hostname. Never call `tethered.activate()` from library code: `activate()` is process-wide and reserved for the host application or local dev. `scope()` intersects with any host policy, so embedding licenseal cannot widen its egress. `tethered.scope()` keeps its policy in a `ContextVar`, which does **not** cross thread boundaries (PEP 567): a registry fetch issued from a bare `ThreadPoolExecutor` worker runs in an empty context and silently bypasses the scope (fail-open). Every fetching threadpool must therefore propagate the caller's context into its workers — route new pools through `licenseal._concurrency.map_with_context` (one `copy_context()` snapshot per task, since a single `Context` can't be entered by two threads at once), the same way the resolution loop (`cli.py`) and the transitive wave-walker do. A raw `pool.map` over a fetcher reopens the egress hole and won't be caught by the unit tests unless a host `tethered.activate()` happens to cover it.
- Requests carry only dependency coordinates `(system, name, version)` plus a static `User-Agent` — never manifest/lockfile contents, file paths, the project name, or credentials. Don't add an `Authorization` header or read `.netrc` / `.npmrc` / `.pypirc` / keyring (no `httpx.NetRCAuth`); the resolution client keeps httpx's `trust_env` default, so `HTTP(S)_PROXY` is honored (licenseal works behind a corporate egress proxy) but `.netrc` is never read implicitly (httpx ≥ 0.28). See SECURITY.md *What leaves the process*.
- License identifiers come only from structured registry fields — PEP 639 `license_expression`, the legacy `license` field when it's an identifier rather than file contents, trove classifiers, lockfile entries. Don't recover identifiers by pattern-matching free-form license-text bodies (LICENSE file contents, copyright headers); those are spoofable and can only safely route deps toward manual review, never to a permissive verdict.
- Dependency names, versions, license strings, reasons, manifest paths, and review notes are untrusted text. Escape them only where they are rendered, in `report.py`: `_printable` (control characters and lone surrogates) under every table, Markdown, and failure-message string; `_escape_md` for Markdown; `Text` cells or `_rich_escape` for the console (never interpolate them into a Rich markup tag); `_url_quote` for anything placed in a URL. Never sanitise them in discovery, the data model, or JSON: removing a character can turn one package coordinate into another.
- The table report (`report.render_table`) must show every column at any width. Give a free-text column `overflow="fold"` and a fixed-vocabulary column `no_wrap=True` as well, and pass each table through `_fit_table` before printing it: off a terminal it widens the console to the table's natural width, on a narrow terminal it lets the columns shrink below their minimum widths. Any non-ASCII glyph the report draws itself needs an entry in `_ASCII_GLYPHS`, because a stdout under a legacy code page cannot encode it; `-o` files are always UTF-8.
- Changes to risk classifications (`analysis/risk.py`), the compat matrix, or reason strings (`analysis/compatibility.py`) ripple into committed docs that embed matrix semantics by hand. Review and update each in the same change — none are auto-generated, and they drift silently:
  - `README.md` — Compatibility matrix table + Risk levels table.
  - `src/licenseal/data/claude_skill.md` — per-verdict walkthrough (the WARNING / INCOMPATIBLE / UNKNOWN bullets in step 4) and the concrete-examples table. Each matrix cell that can flag a dep must be reachable through a per-dep question pattern in this file.
  - `JSON_OUTPUT.md` — the `risk` enum line and the sample `reason` string.
  - `LICENSES.md` — the sample `reason` string in the Details section.
- 100% test coverage required. Run with parallel workers: `uv run pytest -n 8 --cov=licenseal --cov-report=term-missing` (`pytest-xdist` is in the dev deps; `-n 8` cuts wall-clock by ~4-5×).
- Tests use `respx` to mock HTTP calls. Never make real network requests in tests.
- A `hex.pm` 429 is not retried on the ordinary three-attempt budget: `_HostRateLimitWindow` in `resolvers/http.py` pauses every `hex.pm` request until the window reset reported in `x-ratelimit-reset`, bounded by `_HEX_PM_MAX_STALLED_PAUSES` consecutive pauses and `_HEX_PM_MAX_TOTAL_PAUSE_SECONDS` per process. The scan is told through its `RegistryCache`: `on_rate_limit_pause(host, seconds)` fires once when a pause opens (the CLI prints it through `_STDERR_CONSOLE`, the console that draws the progress displays, so the line is not written into a live display), and `rate_limits.abandoned` counts the lookups still rate limited after the bounded waiting, which the CLI reports after resolution. `resolvers/http.py` never imports the CLI. A test that makes `hex.pm` answer 429 must take the `fake_registry_clock` fixture (`tests/conftest.py`) so the pause advances a fake clock instead of sleeping.
- Keep it simple. No unnecessary abstractions, helpers, or error handling for impossible cases.
- When two ecosystems share an identical type or helper, give the shared definition a domain-neutral name both reference (e.g. `_TransitiveDepsFetcher`), rather than aliasing one ecosystem's name to another's (`_DotnetDepsFetcher = _MavenDepsFetcher`). The cross-domain alias couples the two and makes the borrowed name lie about its scope.
- No specific stress-test repository or package names in source or test comments. Describe the pattern (`large Python projects`, `Cargo workspaces`, `packages with extras-heavy transitives`) instead of the project where you happened to observe it.
- No hardcoded benchmark numbers in comments (MB, timings, `~3.3x` style speedups). They go stale and add noise to readers who aren't running the same workload.
- When stress-testing licenseal against external repositories, treat them as untrusted code. Clone and scan them only through the Docker harness in `scripts/stress/`; never clone one onto the host filesystem. Read their manifest and lockfile contents only; never install their dependencies, run their setup or build scripts, execute their code, or import their packages. licenseal is metadata-only — there's no legitimate development reason to execute code from a scan target, and doing so opens an arbitrary-code-execution surface from third-party projects on local disk.
- Branch from `dev`, PR to `dev`. `main` is releases only.

## Verification

Run the full pre-commit suite and the tests before submitting changes:

```bash
uv run pre-commit run --all-files
uv run pytest -n 8 --cov=licenseal --cov-report=term-missing
```

`pre-commit` is the authoritative static gate and mirrors CI — it runs ruff (check + format), ty, bandit, markdownlint, interrogate, vulture, and the SPDX-ID validator. Running only `ruff check` / `ty check` skips bandit, markdownlint, and the SPDX validator, so a green local run can still fail CI. `pytest` is not a pre-commit hook; run it separately (100% coverage required).

### Stress-testing on real repos

For changes that touch discovery, resolvers, analysis, report rendering, or the review flow, also stress-test against third-party repos — at minimum one Python-only, one npm-only, one Rust-only, and one polyglot project. Treat scan targets as untrusted code: read manifests and lockfiles only; never install their deps, run their scripts, or import their packages.

Scan targets are cloned and scanned only through the Docker harness in `scripts/stress/`. Clones live in the `licenseal-corpus` Docker volume, never on the host filesystem. Scans run in a Linux container that mounts the working tree's `src/` read-only, so they always exercise the current code; only licenseal's own output is written to `licenseal-scans/` (gitignored).

```bash
uv run python scripts/stress/stress.py build      # runner image; rebuild when pyproject.toml or uv.lock changes
uv run python scripts/stress/stress.py clone      # shallow-clone the corpus into the volume
uv run python scripts/stress/stress.py inventory  # manifests + lockfiles per clone
```

The corpus list is local: `licenseal-scans/corpus.json`, in the format of `scripts/stress/corpus.example.json`. If it is missing or doesn't cover the ecosystems the change touches, ask the user which repos to add before proceeding. Do not pick repos unilaterally and do not skip the stress-test stages silently. Every action accepts `--only repo1,repo2`.

Skip repos whose primary purpose is distributing offensive payloads, malware samples, exploit binaries, or operational pentest tradecraft (e.g., `metasploit-framework`, `theZoo`, `vx-underground` mirrors, named NSA/APT-toolkit dumps, RAT/loader/stealer source, pentest-tradecraft skill packs). The on-disk binaries trip AV mid-walk — leaving locked directory shells that only release on reboot — and ship no manifest-only signal for licenseal anyway. Filter by repo description and topic tags before cloning, not after; this applies equally to one-off clones and to corpus entries.

**Conventions for stress-test runs:**

- All scratch artifacts (fresh scans, comparison scripts, filled review files, probes) live under `licenseal-scans/`. Never write them to the repo root.
- Report licenseal-side issues only (parser bugs, dropped deps, classification regressions, format-path failures). The scanned repo's actual license findings are not part of the stress-test output.
- Baseline and post-change runs both go through the harness. A scan run on the host is not comparable with one run in the container.
- Save a pre-change baseline per repo before starting: `stress.py baseline` writes `licenseal-scans/<repo>.scan_baseline.json` for `--no-dev` and `<repo>.scan_baseline_dev.json` for `--dev`, and keeps an existing baseline unless `--force` is passed. Repos without a lockfile resolve against live registry state, so retake their baselines immediately before the change.

Run all four stages per repo touched by the change:

**1. JSON parity in both modes.** `--no-dev` is the default; `--dev` exercises dev-discovery, dev-reachability attribution, and the dev→warning downgrade paths — run both.

```bash
uv run python scripts/stress/stress.py fresh   # _fresh_<repo>.json and _fresh_<repo>_dev.json
uv run python scripts/stress/stress.py diff    # fresh vs baseline, written to _diff_summary.md
```

`diff` compares (a) `summary` totals, (b) the set of `(ecosystem, name, version)` keys, and (c) per-dep `(license, risk, verdict, group, depth)` tuples. Zero diff confirms no regression. Any diff has to be explained by the change.

**2. Per-ecosystem verification (polyglot repos).** Total-count parity hides per-ecosystem bugs — verify each present ecosystem actually fired its expected pipeline path (Python lockfile parsed, npm seeds planted, Rust crates resolved, etc.) by comparing the per-ecosystem counts from `stress.py report --label fresh` with `stress.py report --label baseline`. The report also notes any ecosystem whose manifests are present in a clone but contribute zero dependencies.

**3. Markdown report path.**

```bash
uv run python scripts/stress/stress.py markdown   # _fresh_<repo>.md
```

Confirm each file is non-empty, starts with a heading, and contains the expected number of table rows (≈ `summary.total` + header rows).

**4. Gap-fill loop (review mechanism).** Validates `init-review-file` end-to-end.

```bash
uv run python scripts/stress/stress.py gapfill
```

Per repo, this scaffolds a review file from `_fresh_<repo>.json`, replaces every `license = ""` with `license = "MIT"`, places the filled file in the clone, re-runs `check --no-dev -f json`, and removes the file again, so clones don't accumulate state between runs. N is the count from `Note: N flagged dependencies could not be scaffolded ...` — those deps have no resolved version and can't be keyed by the review file. Expected:

- `summary.reviewed` equals the number of filled stanzas
- `summary.warnings + violations + unknown` drops by the same number
- residual flagged count equals N (the unscaffoldable ones)
