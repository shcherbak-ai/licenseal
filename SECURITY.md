# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in licenseal, please report it **privately** using [GitHub's private vulnerability reporting](https://github.com/shcherbak-ai/licenseal/security/advisories/new). Please avoid opening public issues for security vulnerabilities. Confirmed vulnerabilities will be addressed in a patch release.

## Trust boundaries worth knowing

licenseal is a license-assessment tool, not a security primitive. It reads manifests, calls public registries (read-only), and writes only user-requested local outputs (a report, a `licenseal.review.toml` scaffold, or the project-local Claude review skill) — no code execution, no privileged operations.

### Manifest + registry only

The load-bearing architectural constraint: licenseal's input surface is **on-disk dependency manifests + lockfiles** plus **HTTPS reads from a fixed allowlist of public registries**. It does NOT download or inspect artifact bodies (`.jar`, `.whl`, `.tar.gz`, `.crate`, `.tgz`, any other built or source archive — even when the artifact contains structured fields a registry doesn't expose, such as a JAR's `MANIFEST.MF` `Bundle-License` header). It does NOT install or execute scan-target code (no `pip install`, `npm install`, `mvn`, `gradle`, `setup.py`, lifecycle scripts, etc.). And it does NOT honor scan-target POMs' `<repositories>` declarations to discover additional fetch URLs — that path would let an untrusted POM redirect license-resolution fetches to attacker-controlled hosts (SSRF + cross-artifact license misinformation); any registry beyond the hard-coded allowlist requires explicit code-level inclusion with security review (see *Maven fallback list* below).

This constraint is intentional: package archives and scan-target-controlled registry declarations are outside licenseal's trusted input surface.

Three manifest formats can name other files to read: an MSBuild `<Import Project="…">` in `Directory.Build.props` / `.targets`, a `go.work` `use` directory, and a `-r` / `--requirement` line in a requirements file. licenseal follows these only when the value is a relative path. For the first two, parent `..` references are relative, so the target may sit outside the scan root. A requirements include is followed only when it resolves, through any `..` segment or link, to a file inside the scan root; a URL is never fetched, and `-c` / `--constraint` files are never read. A rooted, drive-qualified, UNC (`\\host\share`, `//host/share`), or device (`\\?\…`, `\\.\…`) value is rejected by a lexical check before any filesystem call — on Windows, the first call on such a path can open a connection to a network share — and the manifest that contains it is reported as an analysis gap, as is a requirements include that is a URL, is not a file, or leaves the scan root.

### Network egress

Outbound network access is restricted to fourteen hosts via [`tethered.scope()`](https://github.com/shcherbak-ai/tethered) wrapped tightly around the resolution call only:

- `pypi.org:443` — PyPI JSON metadata API. A release's license is read from that release's own endpoint (`pypi.org/pypi/{name}/{version}/json`), then from its wheel metadata (next entry). When neither declares one, the license of the project's latest release (`pypi.org/pypi/{name}/json`) is reported in its place and marked as an estimate
- `files.pythonhosted.org:443` — the PSF-operated artifact host paired with PyPI, used for PEP 658 wheel-metadata sidecars. The canonical packaging metadata lives in the wheel's own `METADATA` file (the core metadata spec); PEP 658 is the officially-standardized HTTPS mechanism for reading it without downloading the full wheel. Used as a fallback for the minority of packages (~3% of Python deps in measured stress-test corpora) where PyPI's JSON API returns null license fields despite the wheel itself carrying clean metadata (an indexer gap on PyPI's side, not a deliberate design choice). Same operator and trust posture as `pypi.org`; not a third-party service
- `registry.npmjs.org:443` — npm registry API
- `crates.io:443` — crates.io registry API
- `api.deps.dev:443` — deps.dev (Google's Open Source Insights project). A `POST /v3alpha/versionbatch` batch pre-pass amortises registry load across **every deps.dev-indexed ecosystem licenseal resolves** — Go, Python (`PYPI`), npm (`NPM`), Rust (`CARGO`), Java (`MAVEN`), .NET (`NUGET`), and Ruby (`RUBYGEMS`). The endpoint accepts up to 5000 lookups per request, but its response truncates at exactly 100 entries regardless of request size, so licenseal chunks at 100 — a hard correctness ceiling, not a tuning knob — and a scan of N deps is ⌈N/100⌉ POSTs. The stable `GET /v3/systems/{system}/packages/{name}/versions/{version}` endpoint is the per-dep fallback. For **Go**, deps.dev is the *authoritative* license oracle — Go has no manifest license field by design, so a deps.dev miss is definitive (→ UNKNOWN). For the other six it is an *advisory* pre-pass: a batch miss falls through to that ecosystem's own canonical registry (PyPI / npm registry / crates.io / Maven Central / NuGet flatcontainer / RubyGems), which stays authoritative. Returns SPDX identifiers produced by Google's `licensecheck` library — high-confidence Sørensen-Dice template matching over each package's LICENSE file at the version's tagged commit
- `proxy.golang.org:443` — the Go module proxy, used to fetch raw `go.mod` text for transitive edge resolution (`require` blocks). deps.dev's `GetDependencies` sub-resource isn't available for Go — only npm/Cargo/Maven/PyPI per Google's docs — so the proxy is the only canonical source for Go's transitive graph. Same source the `go` toolchain itself consults during builds
- `repo.maven.apache.org:443` — Maven Central, the canonical OSS Java/JVM artifact registry. Apache Foundation-operated; serves raw POM XML at the standard `/maven2/` layout. Primary source for every Java license resolution. An artifact's list of published versions (`{group/path}/{artifact}/maven-metadata.xml`, served beside its per-version directories) is read from the same layout, here and then on the two fallback registries below, only to find the latest release of a Gradle coordinate declared with no version when there is no `gradle.lockfile`; only the version numbers are read from it
- `dl.google.com:443` — Google Android Maven (`dl.google.com/dl/android/maven2/`). Google-operated; hosts AndroidX, Jetpack, Material Design, Firebase, Play Services. Queried as a fallback when Maven Central 404s on a parent POM — required for Android-ecosystem projects whose parents are published only here. Inclusion criterion: recognized vendor, public-read, standard `/maven2/` layout, covers a meaningful fraction of OSS JVM artifacts outside Central
- `repo.jenkins-ci.org:443` — Jenkins Project public repository (`repo.jenkins-ci.org/public/`). Continuous Delivery Foundation-operated; hosts Jenkins core POMs, the `org.jenkins-ci:*` parent chain, and ~2000 community plugins. Queried as a fallback when Maven Central 404s on a parent POM — required for any Jenkins plugin or core-derived project. Same inclusion criterion as Google Android Maven
- `api.nuget.org:443` — NuGet.org flatcontainer, the canonical .NET / NuGet package registry. .NET Foundation-operated (Microsoft); serves raw `.nuspec` XML at `api.nuget.org/v3-flatcontainer/{id}/{version}/{id}.nuspec` and a package's list of published version numbers at `api.nuget.org/v3-flatcontainer/{id}/index.json`. The list is requested only to resolve a version range with no inclusive lower bound or a floating version (`(1.0,2.0]`, `1.*`). Primary source for every .NET license resolution; the modern `<license type="expression">SPDX</license>` form is parsed directly, the legacy `<licenseUrl>` form is mapped via the same known-URL-patterns table the rest of licenseal uses (no prose extraction)
- `repo.packagist.org:443` — Packagist v2 metadata endpoint, the canonical PHP / Composer package registry. Donation-funded; serves per-package version-history JSON at `repo.packagist.org/p2/{vendor}/{package}.json`. Primary source for PHP license resolution when composer.lock doesn't already carry a per-entry SPDX license (which it usually does — the resolver is **lockfile-first** specifically to minimise load on this registry). The license field is the structured SPDX array from each version entry's metadata (no prose extraction). The endpoint serves Composer's minified form, in which a version entry lists only the keys that differ from the entry before it; licenseal expands it before reading a version's license and requirements. Packagist has no batch endpoint, and deps.dev does not index Packagist (only Cargo / Go / Maven / npm / NuGet / PyPI / RubyGems are), so this is the only network source for PHP. Private Composer registries (`repositories: [{"type": "composer"}]` in scan-target composer.json) are NOT honored — same SSRF / cross-artifact-misinformation posture as Maven `<repositories>` and NuGet `<packageSources>`
- `rubygems.org:443` — RubyGems.org, the canonical Ruby / Bundler package registry. Ruby Central-operated; serves per-version JSON at `rubygems.org/api/v2/rubygems/{name}/versions/{version}.json`, latest-version JSON at `rubygems.org/api/v1/gems/{name}.json`, and a gem's version list at `rubygems.org/api/v1/versions/{name}.json`. The list is requested only when a gem has no locked version and its latest release is outside the declared requirement; only the version numbers are read from it. Primary source for Ruby license resolution; `licenses` is a structured array of SPDX identifiers (no prose extraction). The deps.dev `RUBYGEMS` batch path runs first to amortise registry load; the rubygems.org endpoints fill the gap for deps deps.dev's index hasn't classified. Off-registry gems (`GIT` / `PATH` sources in `Gemfile.lock`, `git:` / `path:` gems in a `Gemfile`) are UNKNOWN without a fetch — they have no rubygems.org record. Private gem sources (`source` declarations in `Gemfile` pointing to e.g. a self-hosted Geminabox) are NOT honored — same SSRF / cross-artifact-misinformation posture as Maven `<repositories>`, NuGet `<packageSources>`, and Composer private registries
- `hex.pm:443` — Hex.pm, the canonical Elixir / Erlang package registry (shared by Mix and rebar3). Serves package metadata at `hex.pm/api/packages/{name}` (the package-level `meta.licenses` SPDX array + `meta.links` + `latest_stable_version` + the version number and publication time of each entry under `releases`: a declared requirement is resolved against the versions, and the times tell which release the license belongs to) and per-release transitive edges at `hex.pm/api/packages/{name}/releases/{version}`. Primary — and only — source for Hex license resolution: deps.dev does not index Hex, so there is no batch pre-pass (lockfile-first keeps this to one request per unique package). License is read from the structured `meta.licenses` array (no prose extraction). hex.pm keeps one such array per package and overwrites it each time a release is published, so it is the license of the release published last; for any other release, an older pin included, that license is reported and marked as an estimate (a release that was relicensed upstream is therefore read at the license of the latest publication). Off-registry deps (`:git` in `mix.lock`, `{git,…}` in `rebar.lock`, the git and path forms of `mix.exs`, `rebar.config`, and erlang.mk) are UNKNOWN without a fetch. Requires a `User-Agent` header (which the shared client always sends). Private Hex repositories / organisations (`hex: …, repo: …` declarations in `mix.exs`) are NOT honored — same SSRF / cross-artifact-misinformation posture as Maven `<repositories>`, NuGet `<packageSources>`, and Composer private registries
- `cran.r-project.org:443` — official CRAN. licenseal fetches the canonical `PACKAGES` index (`cran.r-project.org/src/contrib/PACKAGES`) — a DCF index carrying every current source package's `License` and dependency edges (`Imports` / `Depends` / `LinkingTo` / `Suggests` / `Enhances`) — once per scan (the same index `install.packages` / `pak` consult) and resolves every R package's license and transitive closure locally from it. No per-package requests and no community mirror. deps.dev does not index CRAN. The index carries only *current* versions, so a `renv.lock` / `packrat.lock` pin to another version is reported with its pinned version but resolved against current CRAN license metadata (an older release that was relicensed upstream is therefore read at its current license), which the report marks as an estimate, and a package absent from the index (archived, or off-CRAN such as Bioconductor / GitHub) resolves to UNKNOWN. Licenses are read from the structured `License` field and translated from R's grammar (`GPL (>= 2)`, `MIT + file LICENSE`) to SPDX (no prose extraction; a bare `file LICENSE` with no preceding token → UNKNOWN). Off-registry packages (GitHub / Bioconductor / Local sources in `renv.lock` / `packrat.lock`, `Remotes` entries in `DESCRIPTION`) are UNKNOWN and are never looked up in the index

Direct `crates.io` API calls are serialized at one request per second to match crates.io's published data-access guidance. This limiter applies only to direct `crates.io` GETs; it does not throttle deps.dev's `CARGO` batch pre-pass or other registries. Locked Rust projects usually see no speed impact because `Cargo.lock` supplies the resolved dependency graph and exact pins are answered by the deps.dev batch cache. Rust projects without a lockfile can be noticeably slower because range resolution and registry-walk fallback must use the direct crates.io API under that one-request-per-second cap.

`hex.pm` allows 100 unauthenticated API requests per 60-second window, and licenseal sends no credentials to raise that limit. When `hex.pm` answers `429`, every `hex.pm` request pauses until the reset time the response reports in `x-ratelimit-reset` (65 seconds when the header is absent or unusable, and never longer), then resumes. The pausing is bounded: it stops after three pauses in a row with no non-429 response in between, or after 650 seconds of pausing in one run; past either bound the ordinary three-attempt retry applies and a package that is still rate limited resolves to UNKNOWN. This applies only to `hex.pm`; other registries keep the ordinary retry.

The license reported for a pinned release comes from metadata of that exact release in seven ecosystems: the npm registry's version document, the crates.io version record, deps.dev's module-version record for Go, the Maven POM of the version and the parent POMs it names, the NuGet `.nuspec` of the version, the `composer.lock` entry or the Packagist entry of the version, and the rubygems.org version record. The deps.dev batch and single-version answers are per version too. Three sources are not per release, and a license read from them for another release is reported and marked as an estimate (`~` before the license in the table and Markdown reports, `"license"` in the JSON `estimated` array) rather than presented as that release's own: the CRAN `PACKAGES` index (the current version of each package), hex.pm (one license per package, that of the release published last), and PyPI's project-level endpoint when the pinned release declares no license itself. An estimate does not fail a scan by itself, so a license change between the pinned release and the one the metadata describes is visible only as that mark. See [USAGE.md](USAGE.md#resolution-semantics).

The Maven fallback list is hard-coded in `src/licenseal/resolvers/maven_central.py:_FALLBACK_POM_REGISTRIES`. Scan targets cannot expand it by declaring their own `<repositories>` blocks — the SSRF surface and cross-artifact license-misinformation risk that opens is wider than the trust already granted to scanned manifests. Adding a new entry requires a licenseal release with security review. The same posture applies to .NET: `nuget.config` `<packageSources>` declarations inside a scan target are NOT honored — every NuGet resolution goes through `api.nuget.org`, with deps.dev's NUGET system as the fallback for the rare packages whose `.nuspec` carries neither expression nor mappable URL.

The scope is context-local — licenseal does not flip a process-wide switch on its host. If you embed it in an app that already calls `tethered.activate()` or wraps the call in an outer `tethered.scope()`, the effective policy is the **intersection** of all active policies. The host has the final say. For a tamper-resistant ceiling, the host can use `tethered.activate(locked=True)`. The scope is propagated into the parallel resolution / transitive-walk worker threads (a `ContextVar` does not cross a thread boundary on its own), so every registry call — including the deps.dev batch POSTs — is policy-checked, not just the ones issued on the main thread.

### What leaves the process

Over the wire licenseal sends **only package coordinates and fixed registry-index requests** plus a static client identifier — never manifest/lockfile contents, file paths, the scanned project's name, environment variables, credentials, or telemetry (there is no licenseal-operated endpoint).

- **Request payloads** are one of: a fixed registry-index URL carrying no coordinates at all (the CRAN `PACKAGES` index), a package-coordinate lookup (`name` + `version`, or `name` only for a latest-version or version-list lookup), the deps.dev batch POST body — exactly `{"versionKey": {"system", "name", "version"}}` per entry — or a registry-provided metadata-sidecar URL (the PEP 658 `.metadata` URL, whose path encodes only the wheel's name + version). GET coordinate lookups put name + version (and scope / group) in the URL path.
- **Headers** are static: `Accept` and a `User-Agent` of `licenseal/<version> (<project-url>; <subcommand>)`, where `<subcommand>` is the literal CLI command (`check` / `init-review-file`) — not user data.
- **No credentials are read or sent.** licenseal reads no `.npmrc` / `.pypirc` / keyring, and sets no `Authorization` header. It never constructs httpx's opt-in `NetRCAuth`, and httpx (≥ 0.28) does not read `~/.netrc` implicitly, so a user's `.netrc` is never consulted — even a catch-all `default` entry produces no auth header. Standard `HTTP(S)_PROXY` environment proxies **are** honored (httpx's `trust_env` default), so licenseal works behind a corporate egress proxy; the proxy only ever sees the same package-coordinate requests described above.

The one disclosure inherent to registry-based license resolution: a dependency's **name and version** are sent to the relevant public registry. For OSS dependencies this is non-sensitive; for a proprietary package whose coordinate is shaped like a public one, that name / version is disclosed to the public registry.

Two rules decide what is sent:

- A dependency whose source is a **git repository, a direct URL, or a path** is never sent. It is reported as UNKNOWN **without any network request** under any name, in the deps.dev batch or to a registry, and nothing is downloaded from its source. A path the scan reads (a directory of the scanned project that the scan walks) is the project's own code and is not a dependency at all; an archive, and a directory the scan skips or the user excluded, is a dependency like a path outside the scanned directory. The source forms recognised in each ecosystem are listed in [USAGE.md](USAGE.md#off-registry-dependencies); this section's guarantee covers those forms. One form cannot be recognised from the files and is **not** covered: a Composer package that comes from a version-control repository, an `artifact` repository, or a `path` repository the scan does not read, in a project scanned **without its `composer.lock`** (or with `--no-transitive`, which reads no lockfile). `composer.json` names the repository but not the packages it provides, so the names of those packages are sent to Packagist like any other requirement. The scan reports that `composer.json` as an analysis gap, which fails `--strict`. With the `composer.lock` they are recognised and not sent. The source is written to the report (`origin` in JSON, and in the row's reason) with the user-info part of a URL and its query string removed, so a token embedded in a repository or download URL does not reach a report or a scaffolded review file.
- A dependency pinned to an **alternate index or registry** is sent: a Poetry `source`, a uv index, a `Gemfile` `source` block, a Cargo `registry`, a private npm registry, a `+local` version from an internal mirror. licenseal does not query the alternate registry (see *Network egress*), so it looks the name up on the public registry and reports the public package's license. A private package that exists only on an internal registry therefore has its **name and version disclosed** to the public registry, and resolves to UNKNOWN when the public registry has no such package, or to the license of a public package of the same name when it has one.

### Manual review file

`licenseal.review.toml` is a maintainer-approved override file. A malicious entry can mark a copyleft dependency as MIT and pass strict-mode `licenseal check`. Treat it as security-relevant:

- Require code review on every change to `licenseal.review.toml`.
- Document the rationale for each override in the entry's `note` field.
- Re-validate review entries periodically when their resolved versions change upstream.

## Recommendations

- Run `licenseal check` in CI on every PR; fail the build on non-zero exit.
- For embedded use, also pin the host's `tethered.activate(allow=[...])` allowlist to include licenseal's fourteen registry hosts: `pypi.org:443`, `files.pythonhosted.org:443`, `registry.npmjs.org:443`, `crates.io:443`, `api.deps.dev:443`, `proxy.golang.org:443`, `repo.maven.apache.org:443`, `dl.google.com:443`, `repo.jenkins-ci.org:443`, `api.nuget.org:443`, `repo.packagist.org:443`, `rubygems.org:443`, `hex.pm:443`, `cran.r-project.org:443`.
