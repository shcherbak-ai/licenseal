# Security Policy

## Reporting a Vulnerability

If you discover a security vulnerability in licenseal, please report it **privately** using [GitHub's private vulnerability reporting](https://github.com/shcherbak-ai/licenseal/security/advisories/new). Please avoid opening public issues for security vulnerabilities. Confirmed vulnerabilities will be addressed in a patch release.

## Trust boundaries worth knowing

licenseal is a license-assessment tool, not a security primitive. It reads manifests, calls public registries (read-only), and writes a report — no code execution, no privileged operations.

### Manifest + registry only

The load-bearing architectural constraint: licenseal's input surface is **on-disk dependency manifests + lockfiles** plus **HTTPS reads from a fixed allowlist of public registries**. It does NOT download or inspect artifact bodies (`.jar`, `.whl`, `.tar.gz`, `.crate`, `.tgz`, any other built or source archive — even when the artifact contains structured fields a registry doesn't expose, such as a JAR's `MANIFEST.MF` `Bundle-License` header). It does NOT install or execute scan-target code (no `pip install`, `npm install`, `mvn`, `gradle`, `setup.py`, lifecycle scripts, etc.). And it does NOT honor scan-target POMs' `<repositories>` declarations to discover additional fetch URLs — that path would let an untrusted POM redirect license-resolution fetches to attacker-controlled hosts (SSRF + cross-artifact license misinformation); any registry beyond the hard-coded allowlist requires explicit code-level inclusion with security review (see *Maven fallback list* below).

Full statement of the principle, including the rationale for each carve-out (PEP 658 sidecar reads, deps.dev structured-SPDX returns) and the cases where it constrains what licenseal can recover, lives in [AGENTS.md](AGENTS.md#architecture-manifest--registry-only).

### Network egress

Outbound network access is restricted to fourteen hosts via [`tethered.scope()`](https://github.com/shcherbak-ai/tethered) wrapped tightly around the resolution call only:

- `pypi.org:443` — PyPI JSON metadata API
- `files.pythonhosted.org:443` — the PSF-operated artifact host paired with PyPI, used for PEP 658 wheel-metadata sidecars. The canonical packaging metadata (PEP 643) lives in the wheel's own `METADATA` file; PEP 658 is the officially-standardized HTTPS mechanism for reading it without downloading the full wheel. Used as a fallback for the minority of packages (~3% of Python deps in measured stress-test corpora) where PyPI's JSON API returns null license fields despite the wheel itself carrying clean metadata (an indexer gap on PyPI's side, not a deliberate design choice). Same operator and trust posture as `pypi.org`; not a third-party service
- `registry.npmjs.org:443` — npm registry API
- `crates.io:443` — crates.io registry API
- `api.deps.dev:443` — deps.dev (Google's Open Source Insights project). A `POST /v3alpha/versionbatch` batch pre-pass amortises registry load across **every deps.dev-indexed ecosystem licenseal resolves** — Go, Python (`PYPI`), npm (`NPM`), Rust (`CARGO`), Java (`MAVEN`), .NET (`NUGET`), and Ruby (`RUBYGEMS`). The endpoint accepts up to 5000 lookups per request; licenseal chunks at 100, so a scan of N deps is ⌈N/100⌉ POSTs. The stable `GET /v3/systems/{system}/packages/{name}/versions/{version}` endpoint is the per-dep fallback. For **Go**, deps.dev is the *authoritative* license oracle — Go has no manifest license field by design, so a deps.dev miss is definitive (→ UNKNOWN). For the other six it is an *advisory* pre-pass: a batch miss falls through to that ecosystem's own canonical registry (PyPI / npm registry / crates.io / Maven Central / NuGet flatcontainer / RubyGems), which stays authoritative. Returns SPDX identifiers produced by Google's `licensecheck` library — high-confidence Sørensen-Dice template matching over each package's LICENSE file at the version's tagged commit
- `proxy.golang.org:443` — the Go module proxy, used to fetch raw `go.mod` text for transitive edge resolution (`require` blocks). deps.dev's `GetDependencies` sub-resource isn't available for Go — only npm/Cargo/Maven/PyPI per Google's docs — so the proxy is the only canonical source for Go's transitive graph. Same source the `go` toolchain itself consults during builds
- `repo.maven.apache.org:443` — Maven Central, the canonical OSS Java/JVM artifact registry. Apache Foundation-operated; serves raw POM XML at the standard `/maven2/` layout. Primary source for every Java license resolution
- `dl.google.com:443` — Google Android Maven (`dl.google.com/dl/android/maven2/`). Google-operated; hosts AndroidX, Jetpack, Material Design, Firebase, Play Services. Queried as a fallback when Maven Central 404s on a parent POM — required for Android-ecosystem projects whose parents are published only here. Inclusion criterion: recognized vendor, public-read, standard `/maven2/` layout, covers a meaningful fraction of OSS JVM artifacts outside Central
- `repo.jenkins-ci.org:443` — Jenkins Project public repository (`repo.jenkins-ci.org/public/`). Continuous Delivery Foundation-operated; hosts Jenkins core POMs, the `org.jenkins-ci:*` parent chain, and ~2000 community plugins. Queried as a fallback when Maven Central 404s on a parent POM — required for any Jenkins plugin or core-derived project. Same inclusion criterion as Google Android Maven
- `api.nuget.org:443` — NuGet.org flatcontainer, the canonical .NET / NuGet package registry. .NET Foundation-operated (Microsoft); serves raw `.nuspec` XML at `api.nuget.org/v3-flatcontainer/{id}/{version}/{id}.nuspec`. Primary source for every .NET license resolution; the modern `<license type="expression">SPDX</license>` form is parsed directly, the legacy `<licenseUrl>` form is mapped via the same known-URL-patterns table the rest of licenseal uses (no prose extraction)
- `repo.packagist.org:443` — Packagist v2 metadata endpoint, the canonical PHP / Composer package registry. Donation-funded; serves per-package version-history JSON at `repo.packagist.org/p2/{vendor}/{package}.json`. Primary source for PHP license resolution when composer.lock doesn't already carry a per-entry SPDX license (which it usually does — the resolver is **lockfile-first** specifically to minimise load on this registry). The license field is the structured SPDX array from each version entry's metadata (no prose extraction). Packagist has no batch endpoint, and deps.dev does not index Packagist (only Cargo / Go / Maven / npm / NuGet / PyPI / RubyGems are), so this is the only network source for PHP. Private Composer registries (`repositories: [{"type": "composer"}]` in scan-target composer.json) are NOT honored — same SSRF / cross-artifact-misinformation posture as Maven `<repositories>` and NuGet `<packageSources>`
- `rubygems.org:443` — RubyGems.org, the canonical Ruby / Bundler package registry. Ruby Together-operated; serves per-version JSON at `rubygems.org/api/v2/rubygems/{name}/versions/{version}.json` and latest-version JSON at `rubygems.org/api/v1/gems/{name}.json`. Primary source for Ruby license resolution; `licenses` is a structured array of SPDX identifiers (no prose extraction). The deps.dev `RUBYGEMS` batch path runs first to amortise registry load; the rubygems.org endpoints fill the gap for deps deps.dev's index hasn't classified. Off-registry gems (`GIT` / `PATH` sources in `Gemfile.lock`) short-circuit to UNKNOWN without a fetch — they have no rubygems.org record. Private gem sources (`source` declarations in `Gemfile` pointing to e.g. a self-hosted Geminabox) are NOT honored — same SSRF / cross-artifact-misinformation posture as Maven `<repositories>`, NuGet `<packageSources>`, and Composer private registries
- `hex.pm:443` — Hex.pm, the canonical Elixir / Erlang package registry (shared by Mix and rebar3). Serves package metadata at `hex.pm/api/packages/{name}` (the package-level `meta.licenses` SPDX array + `meta.links` + `latest_stable_version`) and per-release transitive edges at `hex.pm/api/packages/{name}/releases/{version}`. Primary — and only — source for Hex license resolution: deps.dev does not index Hex, so there is no batch pre-pass (lockfile-first keeps this to one request per unique package). License is read from the structured `meta.licenses` array (no prose extraction). Off-registry deps (`:git` / `:path` in `mix.lock`, `{git,…}` in `rebar.lock`) short-circuit to UNKNOWN without a fetch. Requires a `User-Agent` header (which the shared client always sends). Private Hex repositories / organisations (`hex: …, repo: …` declarations in `mix.exs`) are NOT honored — same SSRF / cross-artifact-misinformation posture as Maven `<repositories>`, NuGet `<packageSources>`, and Composer private registries
- `cran.r-project.org:443` — official CRAN. licenseal fetches the canonical `PACKAGES` index (`cran.r-project.org/src/contrib/PACKAGES`) — a DCF index carrying every current source package's `License` and dependency edges (`Imports` / `Depends` / `LinkingTo` / `Suggests` / `Enhances`) — once per scan (the same index `install.packages` / `pak` consult) and resolves every R package's license and transitive closure locally from it. No per-package requests and no community mirror. deps.dev does not index CRAN. The index carries only *current* versions; R licenses are version-stable, so a `renv.lock` / `packrat.lock` pin to an older version resolves to that package's current license (the pinned version is still reported), and a package absent from the index (archived, or off-CRAN such as Bioconductor / GitHub) resolves to UNKNOWN. Licenses are read from the structured `License` field and translated from R's grammar (`GPL (>= 2)`, `MIT + file LICENSE`) to SPDX (no prose extraction; a bare `file LICENSE` with no preceding token → UNKNOWN). Off-registry packages (GitHub / Bioconductor / Local sources in `renv.lock` / `packrat.lock`) short-circuit to UNKNOWN without a fetch

The Maven fallback list is hard-coded in `src/licenseal/resolvers/maven_central.py:_FALLBACK_POM_REGISTRIES`. Scan targets cannot expand it by declaring their own `<repositories>` blocks — the SSRF surface and cross-artifact license-misinformation risk that opens is wider than the trust already granted to scanned manifests. Adding a new entry requires a licenseal release with security review. The same posture applies to .NET: `nuget.config` `<packageSources>` declarations inside a scan target are NOT honored — every NuGet resolution goes through `api.nuget.org`, with deps.dev's NUGET system as the fallback for the rare packages whose `.nuspec` carries neither expression nor mappable URL.

The scope is context-local — licenseal does not flip a process-wide switch on its host. If you embed it in an app that already calls `tethered.activate()` or wraps the call in an outer `tethered.scope()`, the effective policy is the **intersection** of all active policies. The host has the final say. For a tamper-resistant ceiling, the host can use `tethered.activate(locked=True)`. The scope is propagated into the parallel resolution / transitive-walk worker threads (a `ContextVar` does not cross a thread boundary on its own), so every registry call — including the deps.dev batch POSTs — is policy-checked, not just the ones issued on the main thread.

### What leaves the process

Over the wire licenseal sends **only dependency coordinates** plus a static client identifier — never manifest/lockfile contents, file paths, the scanned project's name, environment variables, credentials, or telemetry (there is no licenseal-operated endpoint).

- **Request payloads** carry only `(ecosystem/system, name, version)`. The deps.dev batch POST body is exactly `{"versionKey": {"system", "name", "version"}}` per entry; GET requests put the name + version (and scope / group) in the URL path.
- **Headers** are static: `Accept` and a `User-Agent` of `licenseal/<version> (<project-url>; <subcommand>)`, where `<subcommand>` is the literal CLI command (`check` / `init-review-file`) — not user data.
- **No credentials are read or sent.** licenseal reads no `.npmrc` / `.pypirc` / keyring, and sets no `Authorization` header. It never constructs httpx's opt-in `NetRCAuth`, and httpx (≥ 0.28) does not read `~/.netrc` implicitly, so a user's `.netrc` is never consulted — even a catch-all `default` entry produces no auth header. Standard `HTTP(S)_PROXY` environment proxies **are** honored (httpx's `trust_env` default), so licenseal works behind a corporate egress proxy; the proxy only ever sees the same package-coordinate requests described above.

The one disclosure inherent to registry-based license resolution: a dependency's **name and version** are sent to the relevant public registry. For OSS dependencies this is non-sensitive; for a proprietary package whose coordinate is shaped like a public one, that name / version is disclosed to the public registry. Dependencies declared as off-registry **git / path sources** (e.g. `GIT` / `PATH` in `Gemfile.lock`, `:git` / `:path` in `mix.lock`, `{git, …}` in `rebar.lock`) short-circuit to UNKNOWN **without any network request**, so they are never sent.

### Manual review file

`licenseal.review.toml` is a maintainer-approved override file. A malicious entry can mark a copyleft dependency as MIT and pass strict-mode `licenseal check`. Treat it as security-relevant:

- Require code review on every change to `licenseal.review.toml`.
- Document the rationale for each override in the entry's `note` field.
- Re-validate review entries periodically when their resolved versions change upstream.

## Recommendations

- Run `licenseal check` in CI on every PR; fail the build on non-zero exit.
- For embedded use, also pin the host's `tethered.activate(allow=[...])` allowlist to include licenseal's fourteen registry hosts: `pypi.org:443`, `files.pythonhosted.org:443`, `registry.npmjs.org:443`, `crates.io:443`, `api.deps.dev:443`, `proxy.golang.org:443`, `repo.maven.apache.org:443`, `dl.google.com:443`, `repo.jenkins-ci.org:443`, `api.nuget.org:443`, `repo.packagist.org:443`, `rubygems.org:443`, `hex.pm:443`, `cran.r-project.org:443`.
